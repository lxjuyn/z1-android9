# Z1 R7 candidate with the Settings crash fix

The November 21 Settings tombstone records `ConnectedDeviceDashboardActivity` throwing in `UsbBackend.updatePorts()` because this port can start without `UsbService`. The Settings fix in `c19a954` tolerates the absent service. The combined system readback confirms Settings APK `6e9aa0dba297e8eb840b565b625716a7939e32a91bdc531187437721663e4b7a`. It also carries Bluetooth stack binary `86f6c3f0de68d417273d7fc869712f2d01b993b7aa2e43e76336a9daee034833`, matching the archived workaround for the controller's rejected feature pages.

The radio-enabled R7 boot keeps the ART startup repair and carries HWC r25 with wake retry (`42b992f`), the Bluetooth vendor transport comparison option (`450e4e8`), and the PCM reopen audio HAL. The three audio slots in the paired system read back as the same newer binary. The default Bluetooth path remains factory-first when NVRAM is ready.

The flash files are on the project HDD in `z1-archive/r7-current-settings-20261123_155141/package/`. The boot SHA-256 is `4a6693405da19df798fdd3423b1b209cf0a05df667a2a6129fa6c5e6772e0ba0`. The system SHA-256 is `d6f08965fe3fa22f0f8f1dd97675a4f06b0b333ba49fd7db9b13a34258ac80b6`. Boot readback verified all three replacement members, and the repeat build was byte-identical. System `e2fsck -fn` and the package checksums passed. The scatter enables `bootimg` and `android` in Download Only.

The November 23 flash completed successfully: all 5,992,448 bytes of boot and all 19 system blocks (943,718,400 bytes) read back byte-identical. ## Unlock reproduction and one-change display comparator

- UART `z1_boot_mainline_20261123_182433.log`: one reset occurred before Linux printed a banner, and one occurred around 0.566 s, while the charger driver was probing (lines 644 and 1468–1471). Android UI, physical touch and Bluetooth are not required for a reset. Proximity to a charger log does not identify the cause.
- In the same capture, regular Settings was requested while keyguard was showing. The original command waited while the boot ID remained unchanged. The separate `wm dismiss-keyguard` then returned zero, Settings became visible at the framework level, Linux stopped at 372.321 s, and Preloader restarted (lines 3683–3813). No Bluetooth page or touch event was needed. This run does not isolate the unlock animation from the pending Settings launch.
- UART `z1_boot_mainline_20261123_184337.log`: the user manually unlocked on a fresh boot. The last kernel output was at 349.516 s after a brightness write and RenderThread DRM access, followed by Preloader (`RGU STA=0`, lines 237–307). No new Settings request was sent by the host. These are transition markers, not proof of a GPU or power fault. The subsequent boot reached completion and was still locked at the read-only sample. The root queue returned `uid=0`, the current boot ID, and an empty `/sys/fs/pstore` at 573 s; there is no retained record from this reset in that boot.

The November 15 R3 pair ran for over 6,828 s but eventually reset. It is a rollback comparator, not an accepted stable release. For a narrower A/B, the archive `z1-archive/r7-unlock-hwc-r24-20261123_185604_GFDdIx/` contains an unflashed R7 boot `129be7f8098c2fe0e1698a8d40d90a72cf70fb7d350889e5b67cfbaee7aa212e`. It replaces only `hwcomposer.z1.so` (r25 to r24); the appended DT changes only `linux,initrd-end`, and a second build compares byte for byte. Use it only with the already verified R7 system `d6f08965…`; the matching r25 rollback boot is archived alongside it. Confirm the **live** HWC identity in `z1stage` before counting a run, since the staging directory can override image payloads. r24 may lose the r25 wake retry, so a better unlock result does not count as an off/on pass.

Compare locked idle and an unlock straight to Home first, under unchanged supply and with no Settings intent pending. Then test regular Settings and Bluetooth Settings independently. Repeat the same sequence on the single-HAL variant if needed; if early resets persist with both variants, continue the separate battery/external-power and R3 comparison.
