# Z1 DSI/KMS 打通计划（2026-11-08 夜）

目标：让 mainline `mediatek-drm` 接管 DSI，进而使 OVL 硬件合成（`Device` 合成）成为可能。

## 一、已核实的事实（全部来自板上日志或厂商源码）

| # | 事实 | 证据 |
|---|---|---|
| 1 | DRM 组件全部 bind：OVL/RDMA/COLOR/DSI，`[drm] Initialized mediatek ... minor 1`，`fb0: mediatekdrmfb` | 板上日志 |
| 2 | DSI 时钟正常：engine/digital = 266.5 MHz，hs = 96.416 MHz | `Z1DSI: clk engine=... digital=... hs=...`（修复后） |
| 3 | `MODE_CTRL` 可写：3(BURST_VDO) → 0(CMD_MODE) 写后读回 0 | `cmd_mode before=3 after=0` |
| 4 | **`INTSTA` 恒为 0x80000000（DSI_BUSY）**，`CMD_DONE`(bit1) 永不出现 | 多次 `poll CMD_DONE timeout INTSTA=80000000` |
| 5 | 不动 PHY 时现象相同 ⇒ **瓶颈不在 MIPI-TX** | v55：完全跳过 PHY 编程，仍 BUSY |
| 6 | MIPI-TX 寄存器布局与厂商 MT6582 一致（PLL_CON0 0x50、RACK 0x84、CMDQ 0x180、VM_CMD_CON 0x130、PHY LCCON 0x104） | 厂商 `dsi_reg.h` 的 `STATIC_ASSERT` + `dsi_drv.c` 注释 |
| 7 | LK 对 MIPI-TX 只写了 4 个寄存器（0x10011074、0x10011848/4c/50），且值在 v55 读回仍存在 ⇒ PHY 由 LK 配置后一直有效 | `lk.bin` 0x2c764 起的 `{addr,val,mask}` 表 + v55 `PHY page800` dump |
| 8 | 厂商发送 HS DCS 写命令时**轮询 BUSY**（不是 CMD_DONE），超时 >50ms 则 `DSI_Reset()`，最后写 `INTSTA=0` | `dsi_drv.c:1356-1373` |
| 9 | 厂商清除 `CMD_DONE` 的方式是写位 0（`OUTREGBIT(INTSTA, CMD_DONE, 0)`），读命令需先清 `RD_RDY` 再 `RACK` | `dsi_drv.c:308-320` |

| 假设 | 状态 |

## 四、v56 之后的决策树

1. **v56 成功（BUSY 清、无 timeout）** → 面板收到 DCS 命令 → 检查屏幕是否出图 → 继续 OVL 验证（`modetest`）。
2. **v56 仍 BUSY 超时** → 执行 D：在 `mtk_dsi_host_transfer` 里切命令模式前停 RDMA 并断开 mmsys 路由（需给 `mtk_disp_rdma`/`mtk_crtc` 加 stop/start）。
3. **停上游后仍 BUSY** → 执行 E：发送前 `mtk_dsi_clk_hs_mode(dsi, 1)`（厂商 HS 命令路径），并检查 `DSI_PHY_LCCON` 的 HS/LP 状态。
4. 三条都失败 → 结论：MT6572 的 DSI 命令通道不可用，转"路线 B"（保持 LK 的 DSI 视频流，只接管 OVL/RDMA），并明确记录：这条路拿不到 `Device` 合成所需的 modeset，只能做零拷贝翻页。

## 五、工作纪律（今晚踩过的坑）

- **禁止并发刷写/搬移脚本**：所有刷写脚本用 `flock` 单实例；搬移脚本先 sha256 校验再删原件。
- 每次只改一个变量，改前备份，改后 `git commit + push`。
- 每条结论必须有板上日志或源码行号；不确定的明确标注"未验证"。
