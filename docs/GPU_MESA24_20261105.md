# Mesa 24.0.9 重建与 v19 镜像 — 2026-11-05 深夜

## 为什么要换掉 19.1.8

板上实测（同一 boot.img，只换 system 分区）：
- 含 **Mesa 19.1.8** → 彩虹条；内核同时报 20 条 `gp error irq state=4000 status=3`
  （`LIMA_GP_IRQ_PLB_INVALID_CMD`，GP 拿到非法命令流被中止，渲染目标保持未初始化内容）。
- 不含 mesa（swiftshader）→ 正常的 LineageOS 二屏。

而同一条内核路径在 `z1_lima_offscreen_command_submit_20260717_231356.log` 里画出过
正确三角形（`TRIANGLE_CENTER_DIFF_CHECK=PASS`）—— 所以问题在用户态。
关键差异：**19.1.8 的 `lima_drm.h` 副本与内核 UAPI 不一致（缺 `LIMA_BO_FLAG_HEAP`），
而仓库里的 Mesa 24.0.9 与内核头逐字节相同**（sha256 `118eafe6…`）。

## 构建（`mesa24-build` agent 完成，实测 64.7 s）

```
meson setup lima-build-24-z1b mesa_src --cross-file=mesa_android/mesa-arm32-z1.cross \
  -Dgallium-drivers=lima,swrast -Dvulkan-drivers= -Dglx=disabled -Dplatforms=android \
  -Degl=enabled -Dgbm=disabled -Dllvm=disabled -Dgles1=disabled -Dgles2=enabled \
  -Dshared-glapi=enabled -Dzstd=disabled -Dvideo-codecs= -Dbuildtype=release \
  -Dandroid-stub=true -Dandroid-libbacktrace=disabled -Dplatform-sdk-version=28 \
  -Ddri-search-path=/vendor/lib/dri
```

`-Ddri-search-path=/vendor/lib/dri` 是**必须**的：上一次 24.0.9 部署失败（r5h）
就是因为默认值 `/usr/local/lib/dri`。

## 两个会让 dlopen 直接失败的坑（19.1.8 时代不存在，因为它是另一套构建）

1. **设备没有 `atrace_get_enabled_tags`**。Mesa 的 android_stub 会调它，
   而镜像里 432 个 `/lib/*.so` 没有一个导出该符号；`RTLD_NOW` 下这本身就足以让加载失败。
   构建侧链了一个 3 行桩。
2. **设备 `libdrm.so` 太老**：缺 `drmDevicesEqual`（egl_dri2 用）和
   `drmSyncobjCreate/Destroy/ExportSyncFile/ImportSyncFile/Wait`（lima winsys 用）。
   构建侧改为**静态链 libdrm 2.4.120**，所以新库里 `libdrm.so` 不再出现在 `DT_NEEDED`。

另外 meson 默认 `SONAME libEGL.so`，必须改成 `libGLES_mesa.so`，否则 bionic 会用
`/system/lib/libGLESv2.so` 的 `DT_NEEDED: libEGL.so` 去满足到我们的 vendor 驱动上。

## 产物（`mesa_android/z1_stage_24/`，sha256 已验）

| 文件 | 大小 | 目标路径 | tag |
|---|---|---|---|
| `libGLES_mesa.so` | 259,368 | `/vendor/lib/egl/` | `same_process_hal_file` |
| `gallium_dri.so` | 11,984,536 | `/vendor/lib/dri/` | `vendor_file` |
| `libglapi.so` | 225,680 | `/vendor/lib/` | `vendor_file` |
| `lima_dri.so` → `gallium_dri.so` | 链 | 镜像里已存在该符号链接 | — |

一个文件够不够？**够**：A9 的 `Loader::open` 只 `load_driver("GLES")` 一次，
按 `libGLES_*` 通配；GL 入口靠 `eglGetProcAddress` → `_glapi_get_proc_address` → `libglapi.so` 里的
16.. 个 `shared_dispatch_stub_*`。实测：旧 19.1.8 的 `libGLES_mesa.so` 导出 **44 个 egl\*、0 个 gl\***，
新的 24.0.9 导出**完全相同的 44 个名字**（双向 `comm` 为空）。
但 `libglapi.so` **必须一起换**（共享 `_glapi_Dispatch`/`Context`）。
