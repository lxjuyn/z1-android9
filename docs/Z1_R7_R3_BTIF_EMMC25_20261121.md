# Z1 R7 R3: BTIF RX and 25 MHz eMMC test package

Status: `HOST_VERIFIED_NOT_DEVICE_TESTED`. This package addresses two plausible failure paths while keeping their tests separable. It does not establish that either reported failure is fixed on hardware.

- **Swipe-associated resets:** R2 sometimes returned directly to Preloader after a swipe, without an orderly shutdown or a visible panic. R2 also had separate page-cache and ext4 failures. R3 changes only `/soc/mmc@11120000/max-frequency` from 50 to 25 MHz to test eMMC timing margin. Sorted DTB decompilation shows one changed property; no-HSQ, 1-bit bus, zImage and ramdisk are retained. A clean R3 run alone would not identify the reset source. Touch IRQ, redraw and power remain possible paths.
- **Bluetooth:** R2 passed Android node ownership and got as far as WMT function-on, then timed out waiting for the RX reply and disrupted Wi-Fi during shared combo recovery. The BTIF DMA receiver previously calculated its unread length from the cached producer wrap, not the current consumer wrap. R3 uses the two live wrap bits, rejects impossible pointer pairs, stops on zero progress and orders DMA payload reads after sampling the producer pointer. Invalid pointers stop the current drain and re-enable the interrupt on the existing exit path, without advancing the consumer or discarding data. Repeated invalid-pointer messages or repeated IRQs without progress would require further board investigation. There is no trace proving that this arithmetic caused R2's missing WMT reply.

The archived R2 system actually used for the earlier run is available (`56bde54564f31bd68c5d1af2693e32628a27ed36f470799e6030d602ed0fda21`). R3 replaces just `/lib/modules/z1-radio/mtk_btif_drv.ko` on that image. The pre/post `e2fsck -fn` checks passed; a read from the final ext4 image matched the module SHA and preserved regular file type, root:root, mode 0644 and `u:object_r:system_file:s0`. An independent build from the pinned archive reproduced the packaged module. The packaged zImage decompresses to the binary produced from the local `vmlinux`; all 88 module imports, including the added `___ratelimit`, are present in that ELF export table. The old and new modules use the same vermagic (`7.0.0-rc7-z1+ SMP mod_unload ARMv7 p2v8`). Actual init/module load still needs board verification.

Local combined package: `z1-archive/r7-r3-btif-emmc25-candidate/` on the mechanical disk. Run `sha256sum -c SHA256SUMS` from that directory. The scatter enables only `bootimg` at `0x2980000` and `android` at `0x4340000`. Use Download Only. The R2 rollback pair is in `z1-archive/r7-priority-r2-20261121.Kpcsnn/profile/` on the same disk. `out/r7_r2_emmc25_boot_only_20261121/` holds the same 25 MHz boot with a scatter that enables only `bootimg`; it provides a storage-only comparison with the original R2 system. R2 is a known failing comparator, not a stable release.

Rebuild the module from `gabin8/mt6572-connsys-modules@e9961becdc889266c3a8b5a488ff741159b6ad80`, archived in `bridge_backups/products/products_wifi_source_repro_20261119_215457/`. Apply `scripts/btgps/bt/patches/0001-btif-rx-vfifo-current-wrap.patch` with `patch -p1`, then run `make -C fork_linux ARCH=arm CROSS_COMPILE=arm-linux-gnueabihf- M=<absolute-source-path>/btif modules` and `arm-linux-gnueabihf-strip --strip-debug` on the resulting `.ko`. The archived `system-inputs.json` pins the base image, the original module and the replacement. Use `scripts/release/z1_build_driver_candidate.py <manifest> --build --output <new-system.img>` to recreate the checked replacement; filesystem write timestamps may differ on a new build.

Before board tests, preserve `/data` and start a confirmed CH340 921600 baud UART capture. First check boot completion and hold an untouched idle baseline (the previous late reset followed more than 14 minutes of idle). Then compare one Android-injected swipe with one physical swipe on the same screen; stop after a reset or new ext4 error. Record the eMMC timing in use and keep Bluetooth off during that comparison. On a stable boot, enable Bluetooth once and capture WMT reply, HCI initialization, discovery, pairing and reconnect; verify Wi-Fi remains usable. If either result is ambiguous, use original R2 system with the 25 MHz boot to keep the clock fixed and isolate the BTIF module. Do not run raw H4 while Android owns HCI. This package carries no new audio, lock-screen or GPS change.
