# Z1 R7 Bluetooth NVRAM readiness

Status: source fix and host-verified candidate complete; candidate unflashed.

## Board evidence

The factory AP records are present on the Z1:

| Record | Runtime size | Owner/mode | Payload expected by `NVM_GetFileDesc()` |
| --- | ---: | --- | ---: |
| `BT_Addr` | 66 | `9997:9997 0660` | 64 |
| `WIFI` | 514 | `9997:9997 0660` | 512 |

The final two bytes are the MediaTek storage checksum. The previous init gate
compared the complete storage size with the payload size, rejected both
records, and therefore did not publish `nvram_init=Ready`.

The same factory image stores `/data/nvram/APCFG/APRDCL/FILE_VER` as 3404
bytes, exactly 46 entries of 74 bytes. The table contains both `BT_Addr` and
`WIFI`. `NVM_GetFileDesc()` opens this version table before returning the
requested record. Board log lines 1078-1081 of
`z1_boot_mainline_20261121_222143.log` show the factory library reaching that
path and failing to open it after the record permission failure.

The older R3 board check also forced `nvram_init=Ready` for one diagnostic.
The factory library then reached `NVM_GetFileDesc()`, but opening `BT_Addr`
failed with errno 13 because Android 9's Bluetooth HAL did not belong to the
legacy UID/GID 9997 tree. Ready alone is therefore insufficient.

## Fix

The radio initializer:

- accepts 64/66-byte `BT_Addr` and 512/514-byte `WIFI`;
- verifies the factory two-byte record checksums for the 66/514-byte storage
  forms and retains the non-zero BT payload check;
- requires the 3404-byte `APRDCL/FILE_VER` version table;
- applies `0770` to the known NVRAM directories and `0660` to the records,
  including `APRDCL` and `FILE_VER`;
- assigns group AID 1050 (`nvram`) without changing payload bytes;
- publishes `nvram_init=Ready` only after access, checksum and shape checks
  pass.

The Bluetooth HAL service uses:

```text
group bluetooth nvram
```

The runtime manifest exposes a dedicated
`--r7-bt-nvram` profile that accepts the storage-record sizes.

1. `nvram_init=Ready`;
2. `sys.z1.radio.bt_nvram_ready=1`;
3. factory `NVM_GetFileDesc()` opens `APRDCL/FILE_VER` and the device records
   rather than falling back with errno 13;
4. HCI initialization progresses beyond the NVRAM retry.

SCO, and A2DP remain separate tests.
