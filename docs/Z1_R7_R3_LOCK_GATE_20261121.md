# R7 R3: grant composer access to the backlight gate

On the running R3 board, the reported frozen desktop still answered UART commands. Android had completed boot, Launcher was resumed, and input dispatch was enabled and unfrozen. `dumpsys power` reported `Asleep` and display `OFF`; pressing the power key restored interaction. This is distinct from the earlier abrupt reboots.

The board reported the expected HWC r19 hash `5e1294dea240ebb31a9623424ccdb27c78617dc6b929dd4b2c85096422e27ad5`. The graphics composer runs as uid 1000, gid 1003 and has no DAC override capability. The HWC opens `/sys/class/leds/lcd-backlight/display_blank` for writing, but the live node had mode 0644 and uid/gid 0. The shipped `init.rc` gave uid 1000 ownership of `brightness` only. SELinux was permissive on the board; it does not bypass the Unix ownership check. The r19 fallback handles a missing gate, not an existing unwritable gate.

The boot-only candidate adds one `chown system system` for `display_blank` beside the existing brightness setup before `class_start hal`. It retains mode 0644; no world write permission, HAL change, or system image change. The guarded builder pins the R3 base, verifies all unrelated ramdisk records byte for byte and recalculates the initrd end. A second build reproduced the first, and the sorted DT diff contains only `linux,initrd-end`. The scatter enables only `bootimg`.
