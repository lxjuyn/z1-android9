## 0. 当前阻塞：电池电压不足，不是软件

**[实证]** preloader 日志：`check VBAT=3034 mV with 3450 mV`

三次 943 MiB system 写入分别在 **86.8% / 22.2% / 19.6%** 失败，签名一致：
```
DeviceClass - USBError(5, 'Input/Output Error')
DALegacy - [LIB]: Data ack failed for sdmmc_write_data
Failed to write ... to sector 137728 with sector count 1843200
```
6 MiB 的 bootimg 写入在同样电压下**成功** → 是小写入电流没到欠压、大写入才触发。

**纪律**：刷写前先跑 `tools/z1_vbat_guard.sh [min_mv]`，低于阈值拒绝刷写。
早期把这件事归因成"USB 链路不稳"是错的。

## 2. 已推翻的旧结论（别再按它们做）

1. **"ProfileManagerService 崩把 system_server 拖死"** — 错。`Slog.wtf` 走 `reportWtf`，
   `AMS.handleApplicationWtf` 对 system 进程固定返回 false（`ActivityManagerService.java:1596-1606`），
   `RuntimeInit` 不杀。BOOT FAILURE 只是日志。
2. **"缺 libssl 要换 supplicant / 补 OpenSSL"** — 错。镜像已有完整 HIDL wifi 栈，
   那个遗留二进制不该被使用；正确做法是退掉服务（已做）。
3. **"`dma_heap` 是黑屏解药"** — 错，真因是 ashmem 缺失。
4. **"我的 dma-buf gralloc 包装库可以上"** — 有 5 个缺陷（见 §3），不应用。
5. **"`-Xnoimage-dex2oat` 能省 8 分钟"** — 错，imageless 下 ART 会 abort（`thread.cc:4006`）。
6. **"把 `arm.noimage` 改名回 `arm` 提速"** — 错，执行即 SIGILL。

## 3. 仍未解决（按优先级）

### P0 ART / boot image（根因已定位到 dex）

> **2026-11-05 更正**：本文早期版本写过"所有 boot jar 的 dex 头部校验和都是错的"，
> **那是错的**。我用 `adler32(bytes[32:])` 计算，而 DEX 规范的 checksum 字段是
> `adler32(bytes[12:])`（SHA-1 才是 `[32:]`）。用正确范围实测，13 个 dex 的
> checksum **全部匹配**（例：`classes.dex` stored `0x844a8d61` = adler32[12:]）。
> SHA-1 确实对不上，但 ART 的 `DexFileVerifier::CheckHeader` **只校验 adler32，
> 从不校验 SHA-1**，所以无害。`tools/z1_fix_dex_checksums.py` 已按正确范围修正，
> 并改为"仅当 adler32 不符才改写"；实测 7 个 boot jar **0 个需要修复**。
>
> 真正的 ART 层缺陷是 **26,065 个 access_flags 违规**（见下），分布在
> core-oj / core-libart / conscrypt / okhttp / framework 五个 jar；
> apache-xml 与 bouncycastle 是**零违规**，APK 与 services.jar 也干净。
**[源码+实证]** `SIGILL` 落在 `boot-framework.oat` 的 `QuickMethodHeader` 内；
imageless 模式必然 abort。根因是 **10 个 boot jar 的 dex 有非法 access_flags**。

- **F1（先做，单变量）**：清掉失效的重定位缓存
  `rm -rf /data/dalvik-cache/arm/*boot*`，判据：`Could not create image space` 与
  `thread.cc:4006` 归零、zygote 连续存活 ≥5min
- **F2（仅当 F1 只换了报错）**：zygote 加 `-Xnorelocate`（选项字符串在 libart 实测存在）
- **F3（根因）**：修 dex 的 access_flags 并**同时重算 adler32 与 SHA-1**；并且
  `OatDexFile` 里的 checksum 必须与 jar 内 dex 一致，否则 oat/vdex 仍会被丢弃

### P1 GPU（dma-buf gralloc 需重做）
**[实证]** 我的包装库缺陷：
- HW_FB 按 fb 尺寸分配 163,840 B，客户端目标需 307,200 B（差 143,360）
- `fb_post` 无格式感知的 memcpy
- fd 换掉后 `base`/`flags` 仍指向 ashmem（仅分配进程可见）
- `close` 继承 `free(dev)` 而 device 在 `.bss` → HAL 重建时 abort
- 无 cache sync（in-tree 版有 `z1_lima_sync_dmabuf`）

**结论：用回 in-tree 25,116 B 的 `gralloc.z1.so`。** EGL 选谁由 `libGLES_<tag>.so`
文件是否存在决定：要 SwiftShader 就别放 `libGLES_mesa.so`。
另外 Mesa 19.1.8 硬性拒绝非 16 对齐的 stride。

### P1 开机动画的"首启优化页 / 常态 LOS"切换
**[冲突未决]** 一个复核说 bind-mount 可用，我的观测是 `BootAnimation::playAnimation` SIGSEGV。
建议改用 `/system/etc/z1_system_id` 作为判据（不要用 build.prop md5），
并且只在没有新 `BootAnimation`/`dex2oat` tombstone 时才写 marker。
