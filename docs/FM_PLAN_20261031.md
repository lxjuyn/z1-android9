# Z1 FM 收音盘点与最小可行路线定案（FM 盘点员）

> 2026-10-31。接续 2026-10-30 媒体素材轮（`out/MEDIA_DEPLOY.md` §4 初判"需大工程"）。
> 本轮只做 FM：原厂件盘点 + 内核侧复验 + 最小可行路线定案。全部结论来自本机离线取证，
> **未上板、未刷写、未碰设备**；只读访问四件基线镜像（debugfs，未复制任何大镜像）。
> 凡未确定处均显式标注。磁盘纪律：全程未复制 >100KB 的新产物，`df -h /` 终值 3.9G 可用。

---

## 一句话结论

**维持"大工程"判定，但修正上轮一处关键前提：FM 内核驱动源码并非"无源码可移植"——
MTK ALPS 系 GPL 内核 dump（如 GitHub `elephone-dev/P9000-Kernel` 的
`drivers/misc/mediatek/fmradio/`，含 `MT6627_FM` 分支）就是现成源码渠道。**
userspace 六小件已收集齐且 sha 级验证（`fm/` 目录，~445KB）；真正缺的是**内核 FM 整层**
（`/dev/fm` 字符设备 + mt6627 芯片驱动 + FM patch 加载者，三法复验全无）。
最小可行路线 = 先通音频（P0-A 前置）→ 移植 fmradio 栈接上已有 WMT 钩子 → 部署六小件 →
插耳机上板实听。不立项内核移植则硬件 FM 不可行（网络电台依赖网络，非离线方案，不作为目标）。

### 1.2 原厂 boot.img ramdisk rc —— `/dev/fm` 与 FM 模式定案

出处 `out/boot_extracted/rd/`（`1/boot.img` 已解 ramdisk）：

- `init.rc:669-671`：`mknod /dev/fm c 193 0` + `chmod 0660` + `chown system media`
  ⇒ **`/dev/fm` = char major 193, minor 0**，属主 `system:media`（与上轮"major 193"判断互证）。
- `init.project.rc:26-37`：`mknod /dev/stpwmt c 190 0`、`/dev/stpgps c 191 0`、`/dev/stpbt c 192 0`、`/dev/wmtWifi c 153 0`（factory major，A9 mainline 的 wmtWifi 已改 155）。
- `init.project.rc:90` `service wmtLoader /system/bin/logwrapper /system/bin/wmt_loader`（oneshot）。
- `init.project.rc:97` `service conn_launcher /system/bin/logwrapper /system/bin/6620_launcher -p /system/etc/firmware/`（class core，**开机常驻加载 combo patch，非 FM 专属服务**）。
- `/etc/firmware/WMT_SOC.cfg`（factory 417B / A9 80B，**文本内容相同**）：
  `coex_wmt_ant_mode=1`、`wmt_gps_lna_pin=0`、`wmt_gps_lna_enable=0`、`co_clock_flag=1`（共时钟）。

**"6620_launcher FM 模式"定案**：`strings` 取证显示它没有 FM 专属模式——它读
`persist.mtk.wcn.combo.chipid`、`stp_open`（"Common Interface: SDIO mode / UART mode"）、
加载 `*_patch` 并校验 fw 版本（"fw Ver in patch matches with firmware version"）。
它是**整颗 combo 芯片的 patch 加载器**；FM 的开/关是 libfmjni 对 `/dev/fm` 的 ioctl，
由**内核侧** FM 驱动经 WMT/STP 完成。上轮 WiFi 计划（`z1a9_gpt/Z1_WIFI_PLAN_20261027.md` B11）
已实证：SOC/AHB 流程里 patch 由内核 WMT 自下载，6620_launcher 多余。

## 2. 内核侧（任务 2）

### 2.1 FM 驱动存在性 —— 三法复验，全零

| 方法 | 命令（实测） | 结果 |
|---|---|---|
| ① 文件名 | `find fork_linux/drivers/misc/mediatek -iname '*fm*'` | **空** |
| ② 符号表 | `grep -icE 'fm_drv\|stp_fm\|wmt_fm\|fm_low\|mtk_fm\|combo_fm' fork_linux/System.map` 与 `a9_wt/System.map` | **均 0** |
| ③ 源码符号 | `grep -rln 'do_fm_drv_init\|MT6627fm_low_ops_register\|mt_fm_probe\|fm_radio' fork_linux/drivers/` | **0 个源文件**（仅 tda18271 等 media tuner 误命中文件名级） |
| ④ 已编模块 | `cat fork_linux/.../connectivity/common/modules.order` | 6 个：`mtk_stp_wmt_soc / mtk_stp_uart_soc / mtk_hif_sdio_soc / mtk_stp_bt_soc / mtk_stp_gps_soc / mtk_wmt_wifi_soc` —— **无 FM 模块** |

对照组（证明取证方法有效）：原厂 `out/boot_extracted/kernel.bin`（3.4.67 机器码）
`grep -aoE 'do_fm_drv_init\|MT6627fm_low_ops_register\|mt6627_fm[a-z_]*\|mt_fm_probe'`
命中 `do_fm_drv_init`×1、`MT6627fm_low_ops_register`×1、`mt6627_fm_cust`×1、
`mt6627_fm_v*`×10（固件路径串）、`mt_fm_probe`×1 —— **原厂 FM 驱动确实 built-in 且读
`/etc/firmware/mt6627/mt6627_fm_v*_{patch,coeff}.bin`**。同一个 grep 在 mainline 树上零命中，方法有效。

### 2.2 CONNSYS 链 FM 走向定案

**FM 与 BT/GPS 同乘 CONNSYS（WMT 仲裁 + STP 传输），userspace 入口是 `/dev/fm`(c 193:0)。**

- **WMT 半边已在 mainline 就绪**（本轮逐行复核）：
  - `common/core/include/wmt_func.h:33-36`：`#if 1//defined(CONFIG_MTK_COMBO_FM)` → `#define CFG_FUNC_FM_SUPPORT 1`（硬编码开）；
  - `common/core/wmt_func.c:463-478`：`wmt_func_fm_ctrl / wmt_func_fm_on / wmt_func_fm_off` → `wmt_core_func_ctrl_cmd(WMTDRV_TYPE_FM, …)`；
  - `common/core/wmt_core.c:53,72,800,1149,1246,1690`：FM 的驱动状态跟踪（DRV_STS_POWER_OFF 等）在编译单元内；
  - `common/include/wmt_exp.h:65`：`WMTDRV_TYPE_FM = 1`。
- **缺的整层**：①`/dev/fm` 字符设备（mainline `common/linux/pub/` 只有 `stp_chrdev_bt.c`(major 192, 源码 `BT_DEV_MAJOR`)、`stp_chrdev_gps.c`、`wmt_chrdev_wifi.c`，**无 `stp_chrdev_fm.c`**）；②FM 芯片驱动（fm_drv + mt6627_fm_link/native，读固件、下发 patch、实现 FM_IOCTL_* 与 RDS read/poll）；③WMT func_on(FM) 的调用者（mainline 里没有任何代码调它——WiFi 有 `/dev/wmtWifi` 对应 `wmt_chrdev_wifi.c`，FM 没有对应物）。
- **A9 已通的对照链**（`Z1_WIFI_PLAN_20261027.md` + 板载日志）：`mtk_btif_drv → mtk_stp_wmt_soc → (bt/gps/wifi chardev) → wlan_gen2`，`echo 1 > /dev/wmtWifi` 即 `mtk_wcn_wmt_func_on(WMTDRV_TYPE_WIFI)`。FM 若移植，走的是同一 WMT 核心的 `WMTDRV_TYPE_FM` 分支。
- **FM 固件**：v1 patch+coeff 已有（§1.1）。`WIFI_RAM_CODE_SOC` 内是否含 FM patch handler **离线无法判定**（维持上轮标注）。
- **天线/耳机**：`accdet` 在 mainline 在位（`sound/soc/codecs/mt6323-accdet.c` + `System.map` 1 命中）；FM 天线=耳机（两代 FMRadio dex 均有 `isAntennaAvailable`/`NoAntennaDialog`，上轮已证）。不插耳机 app 直接拒绝运行。

### 2.3 音频通路依赖（FM"能听见"的前提）

- `sound/soc/codecs/mt6323.c` **没有 FM/LINE 输入 DAPM 路径**：`grep -nE 'FM|LINE'` 仅 3 处命中且全是 `SNDRV_PCM_FMTBIT` 里的子串（FORMAT 行）——零真实 FM/LINE widget（两法：grep + dts 注释所列路由仅为 DAC 播放链）。
- dts `mt6572-z1.dts:314-351`：`sound` 节点现为 `status = "okay"`（**比上轮报告"disabled"前进了一步**），`audsys` 亦 okay；但音频真正出声仍卡在 pwrap write-deny / HAL 命名空间线（上轮 §4 的 r5g/r5i 音频线问题，不在本轮 scope）。
- **FM 声音依赖主音频链先通**：即使 FM 射频通了、搜到台，无 DAPM FM 输入路径 + 音频 HAL 不出声 = 有台无声。顺序不可颠倒。

## 3. 最小可行路线（任务 3）

### 判定：**大工程、可立项（修正上轮"无源码"前提）；不立项则不可行，直说**

**上轮修正**：上轮 §4 称"无源码可移植（GitHub 渠道未查到）"。本轮网络检索证实渠道存在：
GitHub `elephone-dev/P9000-Kernel` 的 `drivers/misc/mediatek/fmradio/Makefile` 明确含
`ifeq ($(findstring MT6627_FM,$(CONFIG_MTK_FM_CHIP)), MT6627_FM)`（MTK ALPS 标准布局）；
MT6572/6582 世代（3.4.67 同代）的设备内核 dump 亦普遍带 `fmradio/` 目录
（如 [bgtwoigu/6592_6732_drv](https://github.com/bgtwoigu/6592_6732_drv) 一类泄露/释放源）。
**未确定**：P9000 树（MT6755/3.18 世代）与 6572/3.4.67 的 fmradio 源差异度需拉源码比对——列为本路线第 2 步的第一个动作。

### 工作分解（按依赖序，估"周"级）

| 步 | 内容 | 前置/证据 |
|---|---|---|
| 1 | **音频出声**（P0-A，全项目音频线）：pwrap write-deny + audio HAL 命名空间 | FM 射频通也无 DAPM FM 输入路径（§2.3），无声 |
| 2 | **拉 GPL 源码比对**：`fm_drv.c` + `mt6627_fm_{link,native,host_if,conv}.c` vs 3.4.67 需求；优先找 mt6572/6582 同代 dump | 渠道已定位（上文）；差分基线=原厂 `kernel.bin` 符号 |
| 3 | **内核移植**：chardev `/dev/fm` c 193:0（**务必 device_create**，本项目 gps 模块踩过"注册 region 无 device_create"坑）+ fm_drv + mt6627 chip ops + FM_IOCTL ABI + 接 `wmt_func_fm_on`(WMTDRV_TYPE_FM) + request_firmware 路径对齐 `/etc/firmware/mt6627/` | WMT 钩子已在（§2.2）；固件已有 v1 |
| 4 | **userspace 六小件**（~442KB，sha 已落账）：`FMRadio.apk`(los14 `com.android.fmradio`, minSdk21/target23, 无内嵌 so) + `libfmjni.so` + `libfmcust.so`（NEEDED=cutils/dl/media/**libc++**/c/m —— r5k 全在：`libc++.so` 636,332B 实测在位）+ v1 固件 + cust.cfg；进 priv-app + privapp 白名单 + SELinux（permissive 期无险） | `fm/los14_7.1/` 已收齐；**los14 族无需 libxlog**（readelf UND 实测 0 个 xlog 符号；`__xlog_buf_printf` 依赖属工厂族 libfmmt66xx） |
| 5 | **上板**：插 3.5mm 耳机（=天线）→ logcat `FMRadioService`/`/dev/fm` open → 搜台 → **实听** | accdet 已在；不插耳机 app 拒跑 |

### 如果不立项（诚实结论）

**硬件 FM 不可行**——`/dev/fm` 没有任何内核代码会创建，libfmjni 首个 ioctl 即 ENXIO，
任何 app 层补救（装 apk、换 HAL）都无效。唯一替代是**网络电台 app**，但依赖先通网络
（r5k WiFi 线仍带条件），且与听力机"老人离线使用"场景相性差，不作为目标方案。

### 未确定项（不猜）

1. `WIFI_RAM_CODE_SOC` 是否含 FM patch handler——需上板 `cat /proc/driver/wmt_dbg` + FM func_on 实测。
2. P9000/ALPS fmradio 源与 3.4.67 的 ioctl ABI 差异度——需拉源码比对（路线第 2 步）。
3. 本机 combo 的 FM DSP 实际身份（6620-gen2 WiFi 核 + 6627 族 FM 核混装证据并存：`drv_wlan/mt6620` 树 vs `mt6627` 固件串）——需上板读 chipid 后选对 chip ops。
4. A9 板上 6620_launcher（los14 版）在 A9 上是否可运行（API 差异）——但按 B11 它在 SOC 流程里本就多余，不构成路线阻塞。
