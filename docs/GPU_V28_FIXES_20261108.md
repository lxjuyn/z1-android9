# v28：二屏修复（GLES1）+ 监控脚本修复 + GPS 不再阻塞

## 一、二屏（bootanimation）为什么起不来 —— 根因不是 fd -1

`failed to get driver name for fd -1` 三行 **SurfaceFlinger 也在打**（pid 475，同一时刻），
SF 打完照常拿到 lima。所以它是 Mesa 在 Android 上每次 probe 的良性噪音：

- `droid_probe_device()` → `dri2_create_screen()` → `egl_dri2.c:779`
  `loader_get_driver_for_fd(dri2_dpy->fd_display_gpu)`，而 `fd_display_gpu` 要等
  `droid_open_device()` 成功后才赋值，此刻还是 -1 → 必然打印这两行 → render-gpu 那份照建。

**真正的死因**：AOSP 的 `bootanimation` 调 `eglCreateContext(display, cfg, 0, NULL)`
（反汇编 `libbootanimation.so` @0x62b8 `movs r3,#0`），按 EGL 规范 NULL attrib 默认 **ES 1.0**；
而我们编 Mesa 26 时用了 `-Dgles1=disabled` → 创建 ES1 上下文直接失败 →
`EGL_NO_CONTEXT` → AOSP libEGL 返回 **EGL_BAD_MATCH(0x3009) @ eglApi.cpp:1017**
（`eglMakeCurrent` 那行是次生症状）→ `readyToRun()` 返回 -ENODEV → 二屏永远不出现。

## 二、修法（已做）

1. **Mesa 26 重新配置成 `-Dgles1=enabled` 并重编**（影响的是 `libgallium_dri.so`，
   不是 libEGL：libEGL 重建后哈希不变，gallium 从 17,417,404 → 17,428,828 B）。
   用 qemu + 设备自己的 linker 实测：
   ```
   eglCreateContext(NULL attrs) = 0x40aad0f0     ← 修前是 0x0
   eglCreateContext(ES2)        = 0x40aad550
   ```
   并且这个验证是从**构建出的镜像里 dump 回来的那份**跑的，不是构建树。
2. **`z1_gpu_watch.sh` 有必死 bug**：GPU 健康（0 错误）时每 5.6 秒退出一次，
   22.7→680 s 重启了 **113 次**，等于从没真正监控过。已换成修好的版本
   （`/tmp/limahealth/z1_gpu_watch.fixed.sh`，158 行，语法通过）。
3. **GPS HAL 换成 stub**（v27 已做）：`GnssLocationProvider.isSupported()` 是
   `IGnss::getService("default", false)`，服务未注册时会**无限等待**；原 HAL 的 open()
   卡在连 mnld 的 socket。stub 让服务能注册、init 立即返回，system_server 不再被 Watchdog 杀。
