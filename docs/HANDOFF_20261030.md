## 2. 本会话完成清单（全部已 push）

### 2.1 r5h（GPU 卡顿根因修复，复核 PASS）
- **判定**：10-20 那次开机已整链跑通过 Mali400（SurfaceFlinger renderer=Mali400 / Mesa 19.1.8），后来被不兼容的 Mesa 24 盖掉。
- **修复**：删 Mesa 24 `libEGL_mesa.so`（备份在镜像内 `/.r5f_gpu_backup/`），装回 Mesa 19.1.8 栈（`libGLES_mesa.so` 94,488B + `gallium_dri.so` 4,662,060B + 3 symlink）+ `ro.hardware.egl=mesa`（写镜像根 `/build.prop`）+ perf 3 键（nobootanimation/dex2oat=2/lmk.debug=false；disable_bg_dexopt 有意不加）。
- **xattr**：69+6 文件补 security.selinux。脚本 `z1a9_gpt/scripts/r5h_apply/` 与 `r5h_xattr/`，报告 `z1a9_gpt/scripts/r5h_apply/R5H_APPLY_20261030.md`（§6 上板验收清单）。
- **light HAL 判定不部署**：真缺口是内核无 backlight LED 节点（归后续 dts 轮），部署了也 ENOENT。

### 2.2 r5g→r5i（音频 HAL 终局，复核 PASS）
- **ABI 判定**：交接文档里"PoC 的 HMI id 写错"是**误报**——libhardware `hw_get_module_by_class` @0x8f4 确实 strcmp id，但 PoC 本来就是 `"audio"`，一字未改。
- **部署形态**（文件级取证过）：只替换 **shim 路径** `/vendor/lib/hw/audio.primary.mt6572.so`（14,060→8,196B，sha `73d22b25`）——AudioFlinger 按 ro.hardware=mt6572 先命中此路径；两个 20,844B null stub 留着无害。源码 `z1a9_gpt/scripts/r5g_audio/`。
- **r5i = r5h + 音频**（主会话亲融合，逐段校验：build.prop 3621B/mesa 件/标签全保持，e2fsck clean）。

### 2.3 R6 内核 + R6 boot（ready，复核 PASS）
- config 仅 +`CPU_THERMAL`/`MTK_PMIC_THERMAL`（连带 CPU_FREQ_THERMAL/SCHED_HW_PRESSURE）；`"Failed to read cpu-freq"` 串在 R6 payload **0 命中**（R5 板上 73 次）。`z1_charger.ko` 顺产（`out/z1_charger_stage/`）。fork_linux 提交 `ed09ec75b`。
- **R6 boot 组装**（主会话亲做，逐段校验与 r5c 全同仅换 zImage）：`out/z1_r6_boot/boot.img`（ee2874c8）。**⚠ dtb 用 r5c 的（1a2c5689），勿用树里旧 dtb**——该陷阱已由 2.4 彻底消除。

### 2.4 r5c dtb 世系缺口闭环（本会话最后一块硬骨头）
- **谜底**：r5c 打包换了新 ramdisk（1,977,962B，body 0x1e2c6a），initrd-end `0x842e2c6a` 只 patch 进过打包 dtb，**从未入树**——从树重编 dtb 得到的是 r5_boot 旧代（initrd 差 518B）。
- **修复**：initrd-end 入树 + 注释溯源，fork_linux 提交 **`538dba7a1`**（已 push）。**验证：`make dtbs` 产出 sha = 1a2c5689，与 r5c boot 内 dtb 逐字节一致。内核树现在 defconfig（round-trip 仅差 1 项）与 dtb 双闭环可复现。**

### 2.5 侦察结论（素材已落盘，未部署）
- **WiFi 框架 HAL 可行**：jfltexx 全件齐，vintf 全 optional（失败=服务起不来，无 bootloop 风险）。料在 `out/z1_wifi_hal_stage/`（README_DEPLOY.md + deploy_debugfs.sh + SHA256SUMS）。
- **充电器**：检测路径定案 CHR_CON0 bit5 RGS_CHRDET，补丁+ko 在 `out/z1_charger_stage/`。
- 两工作流报告 artifact：`WiFi 框架 HAL + 充电器攻坚报告`、`音频 HAL 部署报告 (r5g_final)`、`GPU 卡顿 + SELinux 标签报告 (r5h_final)`、`内核 R6 报告`（含 GPU clk 树全图 file:line）。

## 6. 本会话自我更正（诚实清单）

1. **vermagic 门禁探针连错两次**：①`strings zImage` 对 XZ 压缩内核恒 0（全部历史交付件都过不了）；②改 XZ 解压后 grep，又踩 magic 假阳性（Corrupt input data）。终版：**逐 magic 候选尝试解压**。教训：门禁探针必须先在真产物上实测。
2. **cp 权限坑**：镜像内 root 属主文件，普通用户 cp 静默失败——`sudo cp` + 回读 sha。
3. **cwd 漂移**：Bash 工具 cd 会话间残留，相对路径 `rm` 静默未遂——一律绝对路径。
4. **r5j 裸副本防误刷**：停止的工作流留下的"干净副本"外观与成品无异，已删并在此记录。
5. **交接前提被推翻**：HMI id 误报（见 2.2）——接手者对前任文档的"待判定"项应重取证。
