## 四、上板验证清单

### 4.1 音频（z1cmd 交互，音频审计员 10 步精简版）
1. `cat /proc/asound/cards; ls /dev/snd/` → card0 + controlC0
2. 无 card0 → `sh /lib/modules/load_audio.sh`（=m 兜底路径，同时裁决 CONFIG_SND=m 之谜）
3. `tinymix set 'Speaker Route Switch' 1; tinymix set 'Speaker Switch' 1; tinymix set 'Speaker Volume' 1`
4. host 生成 48k 1kHz wav → z1cmd base64 上板 → `tinyplay .../z1t.wav -D 0 -d 0` **实听**
5. 播放时 `cat /proc/asound/card0/pcm0p/sub0/status` → STATE_RUNNING；无声则增益抬 idx 2..9 重试
6. 重启后 `logcat -d | grep loadHwModule` → `Loaded primary audio interface`；`tinymix get 'Speaker Route Switch'`=1（rc 生效）

### 4.2 提速（全部自动，看结果）
- 第二轮开机起：`cat /cache/z1diag/bootimg_build.log` 出现 `dex inputs: 15` + `SUCCESS`；`ls /system/framework/arm/` 全套 → **第三次开机 bc 应显著下降**（834s 基线 → 目标 <8min）
- `starting service 'z1_sf_dump'` 从 137 → 2；[z1sf] wrote 从 80MB → <1MB
- bootanim ~30s 退出（`Service 'bootanim' exited`）
- P1 风险提示：dex2oat 写 /system（无日志 ext4）期间保持插线充电，勿断电勿强制重启

### 4.3 mesa（成对刷 boot_chg2 + system_mesa）
① `dmesg | grep "Bringing.*1150000"`（电压下限生效）② `lima bus rate = 416000000` ③ logcat `renderer : Mali400 / vendor : lima`（mesa 接管）④ bootanim 后 ~36s gralloc 分配窗口不再全场静默 + bc=1。若冻：SwiftShader 对照轮也冻 = 基线回归（查 cadence 之谜的 /vendor 现场覆盖损失）；仅 mesa 冻 + lima job timeout = 电压层 → LEDGER P1。

## 五、已知问题与 P3 登记

1. **NTC 真标定**（P3）：gab TEMP 现返回占位 250；需实板两点测量后做查表（厂商 39kΩ 表不匹配 Z1 的 112.6kΩ 反推值，不移植）。
2. **cameraserver/drm/mediadrm/gnss/bt/sensors 延后**（P4 后半）：本轮保守未做，板上 ps 交叉后逐项加。
3. **crng 8s 等待**（P3）：init 疑阻塞 getrandom，无低成本解，缓做。
4. **ramdisk 轮欠账（批次 C 剩余）**：z1_sf_dump oneshot、z1_heartbeat.sh psy 名修复、exec_background 5 行死代码清理——都需按 `a9_wt/tools/z1/z1_a9_mkramdisk.sh` 管线一次 ramdisk 轮（勿单开）。
5. **z1_bootimg_build.sh 修复版**在 out/z1_r5_system/system_all.img 内（/bin/），host 源 = 本轮 /tmp 加工版；out/sf6_files/ 的旧版（remount / bug）勿再用于打包。
6. **cadence 之谜**：板上 /vendor 有未归档临时态（"Z1 nominal 58.43 Hz" 打印源不在任何归档镜像），刷 mesa/all 会覆盖该现场。
7. **SELinux enforcing**、蜂窝 modem：超范围/大工程，未排。
