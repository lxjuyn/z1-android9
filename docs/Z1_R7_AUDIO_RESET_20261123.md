# Z1 R7 direct playback reset, November 23

The same R7 boot `4a669340…` and system `d6f08965…` from the Settings comparison were on the board. The UART capture is `mainline_recon/z1_boot_mainline_20261123_184337.log`. The test ran while the board was still locked, on boot ID `b565430b-a1a2-4399-8c4a-448bfc698c6d`, without an unlock, swipe, Android media request or flash operation.

The first run stopped before changing controls. The Android 9 awk table parser reported `illegal arithmetic operator 345` when run interactively (search for `Z1_MIX_FUNCTION`). A root check confirmed the control nodes and all four controls existed. The probes now query each control by name and parse its reply in the shell. The updated staircase and the 384,044-byte stereo 48 kHz S16_LE tone were checked against their host SHA-256 values on-device.

At about 2131 s the corrected probe saved headphone switch=1, speaker route=1, speaker switch=1 and volume=1. Turning headphones off, writing the speaker route and switch, setting volume=2, and reading PCM playback capabilities all completed. The final stage was `STEP_08_TINYPLAY_BEFORE` at 2139.469 s (lines 3641–3655). The next visible output was Preloader PMIC initialization. There was no PCM-running marker, no shell return, and no route-restore receipt; the new boot replayed filesystem journals. Preloader again printed `RGU STA=0`. This is a whole-device reset before the test could confirm any audible sound; the marker does not identify which open, prepare, trigger, or concurrent power event was responsible. Do not count `tinypcminfo` as playback.

Next comparisons: capture supply and reset reason without changing multiple image payloads, then isolate ALSA open, HW_PARAMS, PREPARE and first write. Test with all analog outputs disconnected in the mixer first, then with only the speaker route on, capturing the codec enable and GPIO140 amplifier event. Ensure each stage emits a marker before its action. Do not blindly repeat full speaker playback after a hard reset. Validate physical sound and routed Android media separately once the board survives the direct test.
