## 0. 零刷写取证（最先，~10 分钟，决定 R1 微观挂点）
控制台 uid 2000 + loglevel7 洪水 → 全部走"写文件两步法"（先 heredoc/echo 落 /data/local/tmp，
再 sh 执行，输出重定向文件后 cat 截段拉回）。
  a) 栈取证（三个进程各一份）:
     for p in $(pidof surfaceflinger) $(pidof zygote) $(pidof bootanim) $(pidof vendor.gralloc-2-0) $(pidof vendor.hwcomposer-2-1); do
       for t in /proc/$p/task/*; do echo "== $p $(cat $t/comm) wchan=$(cat $t/wchan)"; cat $t/stack 2>/dev/null | head -12; done
     done > /data/local/tmp/stacks.txt 2>&1
  b) debuggerd（userdebug 可用; 若挂起进程 ptrace 失败则用 kill -QUIT 触发 tombstone）:
     debuggerd -b $(pidof surfaceflinger) > /data/local/tmp/sf_bt.txt 2>&1
     debuggerd -b $(pidof zygote)       > /data/local/tmp/zy_bt.txt 2>&1
  c) binder 侧: cat /proc/binder/proc/$(pidof surfaceflinger) 与 $(pidof vendor.gralloc-2-0) > /data/local/tmp/binder.txt
     cat /sys/kernel/debug/binder/failed_transaction_log 2>/dev/null >> 同文件
  d) SF 自述: head -c 65536 /cache/z1diag/sf.txt 拉回; ls /data/tombstones/ （zygote 若反复退必留痕）
  e) 判读矩阵:
     - 栈顶在 ashmem_ioctl/ashmem_mmap/ashmem 页 fault(-down_read mmap_sem, D 状态) → R1(a) 内核侧, 进入 §3 补丁线
     - 栈顶在 binder_thread_read/ioctl(BINDER_WRITE_READ), 对端 allocator 栈在 gralloc 内部 → R1(b)/(c) 分侧定案
     - 栈顶在 gralloc 的 fb ioctl(FBIOPAN_DISPLAY)/sync_wait(fence) → R1(c) payload gralloc, 进入 §4 payload 线
     - zygote 栈在 ART heap/ashmem/futex → R2 与 R1 同源性判定; /data/tombstones 有 ART abort → 读 abort message
     - 栈顶在 futex_wait 与 marl/Subzero/llvmpipe 符号 → R5 升级, 走实验 4

## 1. 旁路实验（零刷写零重编，各 ~3 分钟，可逆）
  A) 让 SF 走 fbdev fallback（复刻 10-20 之前时代的通路）:
     setprop ctl.stop vendor.hwcomposer-2-1; setprop ctl.restart surfaceflinger
     预期: SF getService 失败→HWComposer fbdev 路径。若 bootanim 动/桌面出 → 卡点锁定 HWC2/allocator 路径
     （R1(a)/(b) 加重，且此即降级通路候选）; 若依旧冻 → 卡点在更底层(分配/传输)。
     回退: setprop ctl.start vendor.hwcomposer-2-1; setprop ctl.restart surfaceflinger
  B) 观察与 A 串联的 allocator 行为: stop vendor.gralloc-2-0 后 SF 若 FATAL 属预期（P 侧可能无 fallback），
     仅作信息点，不作为修复。回退: setprop ctl.start vendor.gralloc-2-0。
