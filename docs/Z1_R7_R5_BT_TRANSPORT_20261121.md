# R7 R5: Bluetooth startup and H4 transmission

R3 reached WMT function-on and STP readiness, then the factory userspace initializer reported `Get NVRAM restore ready fails!` and closed the controller. No R4 board test occurred. Offline R4 review found that init copied `/z1_libbt-vendor.so` into `/system/vendor/lib/libbt-vendor.so`; R4 still carried the older ramdisk vendor library (`43944199…`). R5 pins both locations to the factory-first/direct-H4 adapter (`a705913c…`). The lock-screen gate change stays in boot.

The Android 9 HAL selects H4 with one descriptor. H4 sends packet type and payload in two `iovec` entries via `writev()`. The old `/dev/stpbt` only exposed `.write`; this kernel's vectored-write fallback invokes it separately per entry, whereas factory `BT_SendHciCommand` sends one contiguous H4 frame. R5 changes the exact pinned MT6572 STP Bluetooth module to `.write_iter` and copies the vector under the existing TX semaphore before one STP send. Plain writes still use the same path. Existing send limits, reset handling and error returns are retained. Only `mtk_stp_bt_soc.ko` changes in system relative to R4. All 35 imports resolve against the matched kernel or the untouched WMT module extracted from R4; modpost reports no unresolved symbols when given the verified WMT exports.

Primary references: [AOSP Android 9 vendor interface](https://android.googlesource.com/platform/hardware/interfaces/+/android-9.0.0_r61/bluetooth/1.0/default/vendor_interface.cc), [AOSP H4 protocol](https://android.googlesource.com/platform/hardware/interfaces/+/android-9.0.0_r61/bluetooth/1.0/default/h4_protocol.cc), [AOSP address selection](https://android.googlesource.com/platform/hardware/interfaces/+/android-9.0.0_r61/bluetooth/1.0/default/bluetooth_address.cc), the local matching kernel `fs/read_write.c`, and `gabin8/mt6572-connsys-modules@e9961becdc889266c3a8b5a488ff741159b6ad80`.

Host verified only. Check the package `SHA256SUMS`, boot readback, ext4 pre/post checks and installed module readback. Flash scope is bootimg and android only. Keep R3 as the hardware-tested rollback comparator. Before enabling BT, check boot stability and verify the installed vendor library matches the ramdisk. Enable once and check fallback selection, HCI Reset and Read Local Version, then check Read BD_ADDR against the device's known identity without posting the address to shared logs. No factory calibration records or address overrides are shipped. If no HCI reply follows successful WMT open, stop Android Bluetooth and confirm it has released the device before using the existing exclusive HCI probe. If HCI works but radio features fail, isolate identity/vendor initialization before changing controller settings. Test scan, pairing, reconnect, Wi-Fi coexistence, and A2DP separately. Earlier SoC resets remain a separate issue.
