# Z1 display candidate with HWC r24

The r24 composer includes the [r23 display changes](Z1_R7_HWC_R23_20261123.md) and the VSync lifetime fix in `e3fad40`. Android 9 unregisters the VSync callback before clearing its receiver. The HAL now stops dispatching the old callback and waits for any invocation already in progress. The worker reads its control flags atomically and passes the cookie that belongs to the VSync callback.

The candidate is `z1-archive/r7-hwc-r24-vsync-20261123_153335/package/boot.img` on the project HDD. Its SHA-256 is `e5019b9527f7b97e9f2b2bb1f4450d48fade69e6be0371732120aec44a5f384a` and its size is 5,990,400 bytes. Pair it with R7 system `f48322725f2f5f53d2d4b3c3b9d92379e0aea715b9d3b04ada03755381843cab`. The rollback boot SHA-256 is `0840aee45d58f56230cc294fb4c97d0365349eae90cff4c6382600b819629260`. The candidate HWC SHA-256 is `3c38dbd038f39fddd4923c1681d63d34490b351a228db1943a778021c8bd2b4b`.

ARM API 28 compilation, ELF and policy checks, 19 power cases, 53 fence cases and nine copy cases pass. Two packaging runs produced byte-identical boot images and the package checksums passed. The board run needs to confirm the active HWC hash, its behavior during composer or framework restart, physical lock and wake, and foreground frame timing. The idle R3 and R7 power and storage comparison remains the first board test.
