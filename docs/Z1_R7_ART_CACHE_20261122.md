# R7 framework crash and peripheral checks, 2026-11-22

The previous factory/Settings image repeatedly lost `system_server`. In `mainline_recon/z1_boot_mainline_20261122_011424.log`, lines 229–336 show the asynchronous ART seed skipping nonempty files in `/data/dalvik-cache/arm`. Starting at line 3712, repeated native crashes at `StrictMode$AndroidBlockGuardPolicy.onCustomSlowCall+24` include both `/system/framework/arm.noimage/boot-framework.oat` and `/data/dalvik-cache/arm/system@framework@boot-framework.art`. A fresh UART capture at 01:33 shows zygote and audioserver cycling while the kernel continues running. The activity service was absent during the live probe. An earlier run (`z1_boot_mainline_20261108_150838.log:28865`) recorded `patchoat` rejecting this same cached `boot-framework.art` against the system image. Together these observations support testing stale cache reuse as a cause of the current failure.

`z1_build_r7_art_boot.py` verifies both input hashes. It checks the system boot ART files, clears generated boot ART files from `/data/dalvik-cache` before init can start zygote, and sets zygote to use the shipped images without relocation or image generation. Cache cleanup failure leaves a `[z1art]` marker instead of starting with an ambiguous mix of files. The old automatic restart hook is disabled to preserve crash evidence. Offline checks reproduced the image byte for byte, checked the appended DTB and checked that cleanup preserves unrelated app dex files.
