# Z1 R7 display candidate with HWC r23

The r23 composer includes the display gate readback and frame timing counters from r20. It writes the full 64-bit layer handle and uses the Pie callback return type (`1cdd3e8`). It requests a client target beneath a partial or translucent bottom layer (`9571afa`) and sends fractional or out-of-range source crops to client composition (`fd18f1a`).

The candidate is `z1-archive/r7-hwc-r23-crop-20261123_153027/package/boot.img` on the project HDD. The boot is 5,990,400 bytes and hashes to `4a679c6c400804239ab3ab418d11e3ec01ba1c815b8e4ec6f8764813f0618cec`. Pair it with system `f48322725f2f5f53d2d4b3c3b9d92379e0aea715b9d3b04ada03755381843cab`. The rollback boot is `0840aee45d58f56230cc294fb4c97d0365349eae90cff4c6382600b819629260`. The builder verified the original ramdisk entries and read back the replacement `hwcomposer.z1.so` with hash `76bc42987ac93e848a99664d5b593cdb1982100b43c7882876132a6209c5bcc1`. The device tree changes only `linux,initrd-end`. Two independent packaging runs produced byte-identical boots.

Android ARM API 28 compilation and the composition policy suite pass. The archive includes results for 19 power cases, 53 fence cases, and nine buffer copy cases. The power and fence runs used ASan and UBSan. The suite also exercises the client target decision when spare planes are available, plus rejection of fractional and invalid crop edges.

The hardware acceptance run needs to confirm the staged HWC hash, physical panel behavior across lock and wake, the first frame after wake, and frame times during foreground scrolling. Callback teardown remains a separate change. The R3 and R7 idle comparison remains the test for whole-device resets and the previously observed file data corruption.
