## 4. light HAL — 不部署（任务 2d）

按 survey.light 判定执行：**不进 r5h**。理由（survey.light 已实证，本轮未重复取证）：
1. 真正缺口是内核侧 `/sys/class/leds/lcd-backlight` 节点不存在（Z1 mainline dts 无
   backlight 节点；原厂走 MT65XX_LED_MODE_PMIC ISINK0，mainline 复现需 leds-mt6323
   + dts 子节点 = R6 工作流）。samsung binary 与镜像内已有的 lights.default.so 写的
   都是不存在的节点 → ENOENT，部署收益≈0。
2. r5f 的 `/vendor/etc/vintf/manifest.xml` 无 `android.hardware.light` fqname
   （survey debugfs 实读 16 HAL 计数=0），A9 hwservicemanager VINTF 校验会拒注册。
3. 若将来部署需三件套齐：manifest fqname + 内核 LED(R6/B3) + 新文件补 xattr。

## 6. 上板验收清单（命令级，按序）

前置：`Z1_VERIFY=0 tools/flash_with_retry.sh android out/z1_r5_system/system.img.r5h_final out/z1_r5_system/system.img.r5f_final 8`
（system 单件即可；boot 不变仍用 `out/z1_r5c_boot/boot.img`。先起 mtkclient 再按开机键；正常开机拔下载线。）

```sh
# --- ① GPU 生效三行（缺一即失败）---
logcat -d | grep -nE "SurfaceFlinger: (vendor|renderer|version)"
#   期望: vendor    : lima
#         renderer  : Mali400
#         version   : OpenGL ES 2.0 Mesa 19.1.8
logcat -d | grep -c "libEGL_swiftshader.so"          # 期望 0（不再加载 swiftshader）
logcat -d | grep -c "loaded /vendor/lib/egl/libGLES_mesa.so"   # 期望 ≥1

# --- ② 属性生效 ---
getprop ro.hardware.egl                    # 期望 mesa
getprop debug.sf.nobootanimation           # 期望 1（开机动画整段跳过）
getprop dalvik.vm.dex2oat-threads          # 期望 2
getprop ro.lmk.debug                       # 期望 false

# --- ③ 渲染节点（首次开机即应存在；若缺席查 ueventd/devtmpfs）---
ls -l /dev/dri/                            # 期望 card0 (226:0) + renderD128 (226:128)

# --- ④ 核心验收：帧耗时（对比基线 中位 5,112ms / 32/32 帧 >1s）---
logcat -d | grep -oE 'Davey! duration=[0-9]+' | grep -oE '[0-9]+' | sort -n | \
  awk '{a[NR]=$1} END{print "n="NR, "min="a[1], "med="a[int(NR/2)], "max="a[NR]}'
#   期望中位降至三位数 ms 量级（UI_JANK_GPU.md 判据：若仍 >1s 说明 GPU 未生效，
#   别调其它东西，走 UI_JANK_GPU.md §6 失败分叉）

# --- ⑤ ANR / Watchdog ---
logcat -d | grep -cE "ANR in com.android.systemui"          # 期望 0
logcat -d | grep -c "WATCHDOG KILLING SYSTEM PROCESS"       # 期望 0

# --- ⑥ SF 侧 dumpsys（renderer 应为 Mali400 而非 SwiftShader）---
dumpsys SurfaceFlinger | grep -iE "GLES:|renderer"

# --- ⑦ 顺手记录（不阻塞，归 R6）---
dmesg | grep -a "bus rate"                 # 25.39MHz 则记下；Mali400 出来即证时钟不挡渲染
dmesg | grep -aE "\[drm\]|lima"            # 期望 Initialized lima 1.1.0 ... minor 0

# --- ⑧ xattr 抽样（为将来 enforcing 铺路，permissive 下无行为差异）---
getfattr -n security.selinux /vendor/lib/egl/libGLES_mesa.so
getfattr -n security.selinux /build.prop
```

失败分叉：照抄 `out/UI_JANK_GPU.md` §6 表格（SF 仍 SwiftShader→查属性与文件；
`eglInitialize failed`→查 MESA-LOADER 打印的搜索路径；`Failed to open /dev/dri/renderD128`
→上板查节点；SF 正常但帧慢→此时才处理 25.39MHz 时钟）。
回滚：刷回 `system.img.r5f_final`；或 gpu 脚本 `--undo`（输入须是已应用镜像，内含 /.r5f_gpu_backup/）。
